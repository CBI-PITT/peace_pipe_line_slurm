# Agent Notes

- 2026-06-12: Updated backend `AGENTS.md` to require reading root and backend notes before changes and appending backend notes after backend file changes.
- 2026-06-15: Added backend reader plugin `reader_plugins/ome_zarr_reader/` with metadata extraction, TIFF slice export, and 100um volume generation for `.ome.zarr` datasets stored as top-level `scale0`, `scale1`, etc. arrays.
- 2026-08-27: Added optional backend job/workflow history updates behind `PEACE_ENABLE_JOB_HISTORY`. The watcher now records dispatching failures, persists returned SLURM job IDs/provenance/log folders for single jobs and readers, and stores per-step workflow dispatch metadata needed for Home-page tracking and forked reruns from a chosen step.
- 2026-09-02: Added validated preprocessing z-range utilities and absolute-index SLURM submission across stretch, histogram equalization, blur, gamma, resize, image calculator, Cellpose denoise, FFT stripe removal, and rembg; subset outputs retain source z-indices and publish `processed_z_range` provenance.
- 2026-09-02: Reused unsuffixed Cellpose raw min/max caches for full-availability inputs and reserved range suffixes for genuinely sparse upstream inputs.
- 2026-09-15: Added atlas-region aggregation to `transform_points`. The `get_structures_df.py` worker now also writes `{cells_basename}_region_counts.csv` (columns `atlas_structure_name`, `atlas_structure_acronym`, `atlas_structure_number`, `cell_count`) with one row per unique valid atlas region sorted by count descending; outside-atlas points are excluded. `main.py` added the matching `out_counts_csv_path` and includes it in the resume check. Per-point CSV and binary TIFF outputs unchanged; no provenance or Flask changes.
- 2026-09-16: Restored the `if not input_path: return None` guard at the top of `ensure_input_metadata` in `start_pipeline.py`. The guard (documented in the 2026-09-10 note) had been lost in a later edit, which broke CSV-input operations like `transform_points` that submit empty `input`/`output`: the watcher raised `FileNotFoundError` on a relative `.dataset_info.json` path before the operation could fall back to the cells CSV provenance. Behavior for non-empty inputs unchanged.
- 2026-09-16: Fixed `transform_points` worker `KeyError: 'full_resolution'`. Operation provenance writers propagate `resolution`/`shape` but not `full_resolution` (only readers do), so `get_structures_df.py` crashed computing the `*_raw_px` columns for reader->operation->detection chains. Added `resolve_full_resolution` which uses the metadata's own `full_resolution` when present, otherwise walks the provenance `source` chain (cycle-safe) and finally falls back to `resolution`. Verified against the failed task's chain (denoise -> imaris_reader, resolves to `[2.0, 0.6, 0.6]`).
