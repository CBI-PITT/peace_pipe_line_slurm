The `get_structures_df.py` worker now also writes `{cells_basename}_region_counts.csv` (columns `atlas_structure_name`, `atlas_structure_acronym`, `atlas_structure_number`, `cell_count`) with one row per unique valid atlas region sorted by count descending; outside-atlas points are excluded. `main.py` added the matching `out_counts_csv_path` and includes it in the resume check. - 2026-09-16: Restored the `if not input_path: return None` guard at the top of `ensure_input_metadata` in `start_pipeline.py`. The guard (documented in the 2026-09-10 note) had been lost in a later edit, which broke CSV-input operations like `transform_points` that submit empty `input`/`output`: the watcher raised `FileNotFoundError` on a relative `.dataset_info.json` path before the operation could fall back to the cells CSV provenance. Behavior for non-empty inputs unchanged.
- 2026-09-16: Fixed `transform_points` worker `KeyError: 'full_resolution'`. Operation provenance writers propagate `resolution`/`shape` but not `full_resolution` (only readers do), so `get_structures_df.py` crashed computing the `*_raw_px` columns for reader->operation->detection chains. Added `resolve_full_resolution` which uses the metadata's own `full_resolution` when present, otherwise walks the provenance `source` chain (cycle-safe) and finally falls back to `resolution`. Verified against the failed task's chain (denoise -> imaris_reader, resolves to `[2.0, 0.6, 0.6]`).
- 2026-09-16: Added `nearest_neighbor` operation (`operations/nearest_neighbor/`: `main.py` + `do_nn.py`, registered in `operations/__init__.py`). CSV input via `cells_path` kwarg; falls back to the CSV-adjacent `.dataset_info.json` for base dirs; `channel`/`resolution_level`/`sequence` from that provenance. Worker auto-detects coordinate style (`z_raw/y_raw/x_raw` µm directly; `axis-0/1/2` scaled by provenance `resolution` with cycle-safe chain walk, `ValueError` if unresolvable), computes 3D NN distance in µm via `scipy.cKDTree` (k=2, self excluded, duplicates 0, non-finite rows NaN), writes `{basename}_nn_distances.csv` (original columns + `nearest_neighbor_distance_um`); when atlas columns are present also writes `{basename}_nn_region_stats.csv` (name/acronym/number, `cell_count`, `mean_nn_distance_um`, `median_nn_distance_um`; outside-atlas excluded; count-desc sort). Single CPU SLURM job, dbscan env, HIGH_RAM, cores=8/mem=64; resume check covers both expected outputs. Verified locally: synthetic spotiflow/dashboard CSVs, duplicate/NaN rows, chain resolution, missing-resolution error, main.py header detection + resume path.
- 2026-09-16: Reimplemented `mean_intensity` (`operations/mean_intensity/`: `main.py` + `do_mean_intensity.py` orchestrator + `run_mean_intensity_z_layer.py` worker, registered in `operations/__init__.py`; backend sources had been lost, only stale `__pycache__` remained).
